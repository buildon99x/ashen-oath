# Ashen Oath — The Severed Gods 핵심 메커니즘 이식 기획서

**기준:** 2026년 10월 8일  
**롤모델:** The Severed Gods, Early Access v0.2.102 (2026-09-11 공개 패치 기준)  
**대상 프로젝트:** `buildon99x/ashen-oath`  
**구현 엔진:** Godot 4.6+  
**목표:** 원작의 실제 게임 규칙, 성장 구조, 선택 구조, 시스템 간 상호작용을 충실히 재현한다.

## 0. 개발 목표와 절대 원칙

Ashen Oath를 **The Severed Gods와 동일한 핵심 재미와 게임플레이 메커니즘을 가진 턴제 로그라이트 RPG**로 고도화한다. 새로운 게임 시스템은 기획하지 않는다. 차별화는 Ashen Oath 고유 세계관, 캐릭터, 아트, 사운드와 서사로 제한한다.

1. **원작 우선:** 원작의 실제 작동 방식을 우선하고 독자적으로 재해석하지 않는다.
2. **전체 시스템 이식:** Break·Sever뿐 아니라 행동 자원, 스킬, 유물, 영웅, 보상, 영구 성장까지 연결해서 재현한다.
3. **임의 간소화 금지:** 구현 난이도를 이유로 성장·전술 규칙을 단순 능력치 증가로 대체하지 않는다.
4. **임의 수치 금지:** 공개 자료에 없는 피해 공식·확률·행동 비용·드롭 테이블은 실기 확인 후 확정한다.
5. **메커니즘 우선:** 기능이 존재하는지만 보지 않고 같은 플레이 판단과 성장 경험을 재현하는지 검증한다.

**목표 게임플레이 루프**  
영웅 선택 및 스킬·유물 구성 → 분기 탐험·전투·NPC 사건 → 약점 공략·Break·Sever(EP·MP 운용) → 스킬·유물 획득 및 강화 → 사망 또는 클리어 → 환생·영구 해금 → 다음 여정.

원작이 공개한 콘텐츠 규모(앞서 해보기 버전의 5명 영웅, 3개 세계, 스킬 100종 이상, 유물 80종 이상)를 최종 이식 목표의 콘텐츠 기준으로 삼는다. 공개 설명과 정확한 게임 공식은 구분한다.

## 1. 핵심 재미 정의

### 1.1 높이별 전술과 신체 부위 절단

- Low/Mid/High 공격 높이와 유효 부위를 판단한다.
- 부위 실드·약점을 공략하여 Break를 만든다.
- 노출된 부위를 Sever하고 적 능력을 영구 제거한다.
- 절단·자세 변화가 공격 가능 부위와 적 행동을 바꾼다.

**핵심 재미:** 적의 신체·행동 구조를 전투 중 변화시켜 전술적 우위를 확보하는 것.

### 1.2 EP·MP 기반 행동 자원 운용

- EP의 획득·배분·소모와 MP 기반 스킬 비용·회복을 재현한다.
- 일반 공격·스킬·Defend·Parry·Counter 등 원작에 존재하는 행동을 이식한다.
- EP 소비가 공격 실행과 강화에 반영되는 조건을 검증한다.
- 공격과 방어의 선택 순서에 따른 결과를 유지한다.

**핵심 재미:** 즉시 공격할지, 자원을 확보할지, 방어할지 판단하는 것.

EP 최대치·획득 공식·행동 횟수·MP 관계는 원작 실기 플레이로 확정한다. 현재의 영웅별 매 라운드 1회 행동 규칙은 기준 버전에 맞게 교체한다.

### 1.3 스킬·유물 시너지와 빌드 성장

- 스킬 획득·장착·교체·레벨업·변형
- 유물 획득·장착 및 스킬 작동 방식의 변화
- 상태 이상·연쇄 공격·버프·디버프의 상호작용
- 전투 보상·Empower를 통한 점진적 빌드 진화

**핵심 재미:** 같은 영웅도 여정마다 다른 스킬·유물 조합으로 전투 방식이 달라지는 것.

### 1.4 탐험·NPC·Karma

- 분기 지도와 전투·이벤트·상점·마을·휴식 탐험
- 영웅별 Hero Sigil을 활용한 NPC 상호작용
- 스킬 계승·적 정보 탐색·동료 영입
- Virtue/Sin 및 Karma 조건에 따른 사건·보상·전투 효과
- 진행에 따라 달라지는 NPC·시설·탐험 조건

**핵심 재미:** 탐험의 선택이 이후 전투와 장기 성장에 영향을 주는 것.

### 1.5 환생과 영구 성장

- 실패·클리어 후 Cycle 재시작
- Soul 계열 영구 성장, 영웅·스킬·유물 해금
- Hero Sigil 강화와 마을 시설·서비스 강화
- 해금 콘텐츠가 다음 여정 선택에 반영

**핵심 재미:** 초기화되는 여정 속에서도 새로운 플레이 가능성이 계속 확장되는 것.

## 3. 전투 시스템 구현 명세

### COM-01. EP / MP / 턴

**요구사항**
1. 원작 행동 순서와 EP 규칙으로 현재 턴 모델을 교체한다.
2. 영웅별 EP 상태·회복·소비를 관리한다.
3. 스킬별 MP 소모 및 회복 조건을 처리한다.
4. EP 배분에 따른 공격 실행과 강화 결과를 재현한다.
5. Defend·Parry·Counter의 비용과 판정 시점을 분리한다.
6. 유물과 상태 이상이 EP·MP·행동 순서에 미치는 효과를 반영한다.
7. UI에 자원·행동 가능 여부·예상 결과를 표시한다.

**실측 필수값:** 라운드 시작·종료, 행동 순서, EP 초기·최대·회복·배분 단위, 사용 시 공격 횟수와 실행 순서, MP 초기·비용·회복, 방어·Parry의 성공·실패 처리, 상태 이상·유물의 처리 순서.

**완료 조건:** 동일 조건의 원작 행동 입력으로 자원·행동 횟수·효과가 일치한다.

### COM-02. 높이와 타깃팅

- 각 스킬에 원작의 공격 가능 높이 규칙을 적용한다.
- 각 부위에 높이·접근 가능 여부·약점·실드 상태를 보유한다.
- Knockdown과 자세 전환 시 유효 타깃을 다시 계산한다.
- 다리 절단 등 신체 높이 변화가 실제 타깃팅에 반영되도록 한다.
- 높이 위반 공격을 제한하고 예외 스킬·유물은 원작대로 처리한다.

**완료 조건:** 유효·무효 공격 높이와 자세 변화 후 타깃이 원작과 일치한다.

### COM-03. Break / Sever

**검증할 상태 흐름:** 정상 부위 → 실드 손상 → Break → 노출·자세 변화 → Sever → 해당 능력 제거.

**구현 항목:** 부위별 실드·체력·약점, 피해 적용 순서, Break 조건, Knockdown 유지·해제, Sever 실행 조건·판정, 절단 후 공격·버프·패턴 제거, 자세와 높이 변화, 최종 처치·승리 조건.

현재 Ashen Oath의 `실드 0 → 다음 공격에서 HP 0 → 자동 절단` 규칙을 그대로 정답으로 사용하지 않는다. 실제 원작의 Sever 실행 조건을 우선한다.

### COM-04. 적 AI와 보스

- 적별 공격·방어·자세·상태 이상을 데이터로 정의한다.
- 부위 파괴 시 연결된 스킬과 행동을 제거·변경한다.
- 보스 페이즈·공격 가능 높이·자세 변화를 반영한다.
- 원작의 단일 적·복수 적·일반·정예·보스 조우 구성을 실측한다.
- 적 행동 선택 및 상태 이상 적용 순서를 재현한다.

**완료 조건:** 같은 부위를 파괴·절단했을 때 이후 적 행동 변화가 일치한다.

## 4. 스킬·유물·성장 구현 명세

### BUILD-01. 스킬

고정 스킬을 데이터 기반 장착 구조로 바꾼다.

**필수 데이터:** 스킬 ID·계열, 공격 속성·높이·타깃, EP·MP 비용, 피해·실드 피해·Break, 상태 이상과 효과 순서, 레벨별 차이, 변형 관계, 연계 공격·유물 트리거, 획득·해금·장착 조건.

**필수 플레이 루프:** 스킬 획득 → 비교 → 장착·교체 → 전투 사용 → 레벨업·변형 → 다음 전투에서 활용.

전체 목표는 원작 Early Access의 스킬 100종 이상이며, 원작의 실제 획득·보상 순서를 참고해 구현한다.

### BUILD-02. 유물

현재의 유물 ID별 개별 조건문을 확장해 원작의 발동 사건을 처리한다.

- 공격 시작·적중·종료
- Break·Knockdown·Sever
- MP·EP 소비·회복
- 상태 이상 부여·해제
- 방어·반격 성공
- 턴 시작·종료
- 적 처치·승리
- Karma·NPC 상호작용

유물 장착 수·중복 가능 여부·발동 순서·스킬 변형 방법은 확인된 원작 규칙만 사용한다.

**완료 조건:** 원작 스킬·유물 조합의 발동 조건·최종 결과를 재현한다.

### BUILD-03. Empower 및 보상

- 전투 종료 보상 순서를 원작대로 처리한다.
- Empower 획득·적용·강화 효과를 이식한다.
- 보상 단계에서 장착·교체할 수 있도록 한다.
- 스킬 레벨과 장착 상태를 전투·보상·인벤토리에 일관되게 반영한다.
- 선택 불가능 조건·중복 처리도 원작 규칙을 따른다.

**완료 조건:** 원작과 같은 전투 후 성장 선택이 가능하다.

## 5. 영웅·탐험·Karma·환생

### PROG-01. 영웅과 Hero Sigil

- 원작 영웅 선택·편성 방식을 이식한다.
- 영웅 고유 능력·Hero Sigil·레벨별 개방 조건을 구현한다.
- 스킬 계승·적 정보 확보·NPC 영입을 원작에 맞게 구현한다.
- 선택하지 않은 영웅이 NPC로 등장하는 조건을 반영한다.
- 동료의 참여·이탈·전투·성장을 원작 방식으로 처리한다.

Ashen Oath의 캐릭터 이름·외형은 독자적으로 유지하되 시스템 역할은 원작 클래스에 대응한다.

### PROG-02. 탐험·지도

현재 고정 9구간을 원작의 월드·지도·노드 구조로 교체한다.

- 3개 월드의 진행·해금 조건
- 분기 경로·노드 배치
- 일반·정예·보스 전투
- 이벤트·상점·마을·휴식
- NPC·동료 상호작용
- 전투 자원 이월
- 지도 상태 저장·복구

노드 수·생성 방식·전투 간격·보스 진입 조건은 실제 원작 기록으로 확정한다.

### PROG-03. Karma

- Virtue·Sin을 변화시키는 선택 및 행동
- Karma 단계와 발동 조건
- Karma 전용 이벤트·전투 효과
- NPC·상점·시설 반응
- 조건부 보상·성장
- Karma 관련 재등장·제한 규칙

원작에서 확인한 트리거 테이블을 기준으로 한다.

### PROG-04. Soul·환생·영구 성장

- Soul 획득·사용
- Fate Prayers: 스킬·유물 해금
- Hero Sigil: 영웅별 성장
- Prosperity Blessings: 마을 시설 성장
- 영웅 해금과 다음 여정 선택지 변화
- 승리·패배 정산 및 Cycle 반영

현재 Vitality / Force / Focus는 원작 구조와 비교해 존치·전환·제거를 판단하며 단순 능력치 증가로 원작 해금 시스템을 대체하지 않는다.

| RewardSystem | 스킬·유물·Empower 보상 |
| PartySystem | 영웅 편성·고유 능력·동료 |
| WorldMapSystem | 월드·노드·분기·상점 |

| MetaProgression | Soul·해금·환생 성장 |
| SaveMigration | 기존 저장과 신규 모델 변환 |

**원칙:** 콘텐츠 데이터에 기준 버전·검증 상태를 기록한다. 효과 처리 순서를 명시하고 동일 입력·난수로 결과를 재현한다. 체크포인트 12의 저장 복구 가능성, 한국어 UI, 애니메이션을 보존한다. 연출과 전투 규칙을 분리한다. 모듈 분리는 새로운 게임 메커니즘이 아니다.

## 8. 구현 로드맵

### Phase 0 — 원작 규칙 동결
기준 버전 확정, 실제 전투·성장·탐험 기록, 시스템별 테이블, 현재 구현과의 차이 명세.  
**통과:** P0 시스템 실제 동작과 필수 수치 문서화.

### Phase 1 — 전투 코어
EP·MP·행동 순서, 높이·약점·실드, Break·Knockdown·Sever, Defend·Parry·Counter, 부위별 적 행동 변경.  
**통과:** 원작 기본 전투를 동일 규칙으로 재현.

### Phase 2 — 스킬·유물·빌드
장착·교체·레벨업, 스킬 변형·상태 이상, 유물 트리거·시너지, 보상·Empower, 인벤토리 UI.  
**통과:** 원작에서 확인된 서로 다른 빌드의 전투 결과 재현.

### Phase 3 — 적·보스
일반·정예·복수 적, 부위별 공격·자세, 보스 페이즈·절단 대응, 텔레그래프·피해 예측.  
**통과:** 부위 상태에 따른 행동 변화가 원작과 일치.

### Phase 4 — 탐험·영웅·Karma
영웅 편성·Hero Sigil, NPC·동료, 지도·상점·마을, Karma, 월드별 진행.  
**통과:** 전투 밖 선택이 원작 조건으로 전투·성장에 반영.

### Phase 5 — 환생·영구 성장
Soul 정산, Fate Prayers, Hero Sigil, Prosperity Blessings, 영웅·스킬·유물 해금, 세이브 및 Cycle.  
**통과:** 패배 후 영구 해금과 다음 여정 선택지가 원작대로 변화.

### Phase 6 — 콘텐츠·검증
원작 EA 기준 5인 영웅, 3개 월드, 스킬 100종 이상, 유물 80종 이상의 기능 범위를 충족한다. 동일 입력으로 원작과 전투·보상·성장을 비교 검증하고 절단 연출·정보 피드백을 맞춘 뒤 Ashen Oath 독자 자산으로 표현한다.  
**통과:** 핵심 전투·성장·탐험에 임의 독자 규칙이 없고 기능 누락이 해소됨.

## 9. 최종 검수 기준

- [ ] EP·MP·턴·방어·반격이 기준 버전과 일치한다.
- [ ] 공격 높이·Break·Knockdown·Sever가 일치한다.
- [ ] 절단한 부위가 적 공격·자세·페이즈에 미치는 영향이 일치한다.
- [ ] 스킬 획득·장착·교체·레벨업·변형이 일치한다.
- [ ] 유물 발동과 스킬 시너지가 일치한다.
- [ ] 보상·Empower 성장 흐름을 재현한다.
- [ ] 영웅·NPC·Hero Sigil·Karma의 상호작용을 재현한다.
- [ ] 지도·상점·마을·환생·영구 해금이 연결된다.
- [ ] 저장·복구 후 동일 전투·성장 상태가 유지된다.
- [ ] 원작에 없는 독자 전투 규칙이 추가되지 않는다.

**제외:** 독자 전투 자원, 새 공격·방어 규칙, 간소화 성장 대체물, 검증되지 않은 임의 수치·드롭률, 별도 로그라이트 메커니즘.

원작의 소스·아트·사운드·고유 대사·캐릭터 표현은 복제하지 않는다. 일반 게임 규칙의 작동 구조를 검증·구현하되 모든 표현 자산은 Ashen Oath의 독자 자산을 사용한다.
