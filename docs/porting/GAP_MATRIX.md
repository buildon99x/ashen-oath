# 현재 구현과 이식 목표의 차이

기준 소스는 사용자 main `793ad0d`의 규칙과 이를 동작 변경 없이 분리한 `21055bf`입니다. 아래의 기존 수치는 **Ashen 프로토타입 수치**이며 원작의 정답으로 사용하지 않습니다. 이식 목표는 사용자가 채택한 기획서에서 가져온 요구 범위이고, 정확한 조건은 Phase0 근거와 실측으로 확정해야 합니다.

| 책임 | 현재 코드에서 확인한 상태 | 이식에서 필요한 변화 | 먼저 확정해야 할 것 |
|---|---|---|---|
| BattleState | 고정 3인이 각 1회 행동한 뒤 적 공격, 단일 거인 HP 또는 모든 부위 절단으로 승리 | 실제 영웅/NPC 행동 순서·승패 및 추가 행동 상태 | 원작 턴·행동권·승리 조건 |
| ActionEconomy | EP 없음. 집중 비용은 0/1/2/3, 방어 +2, 라운드 +1 | EP 배분과 MP를 서로 다른 자원으로 처리 | 초기·상한·획득·소모·실행 횟수·회복 순서 |
| TargetingSystem | 공격 타입과 선택 부위만 검사. Low/Mid/High는 선택 라벨이며 높이 제한 없음 | 스킬별 유효 높이와 자세 변화에 따른 타깃 재계산 | 각 공격의 도달 높이, 자세와 예외 규칙 |
| BodyPartSystem | 방어막 0이면 영구 붕괴. 이후 부위 HP0이면 자동 절단. 별도 Knockdown 수명 없음 | 확인된 Break·Knockdown·Sever 상태 전이 | 절단 명령 여부·조건·판정·비용, 회복과 반복 붕괴 |
| SkillSystem | `legacy_content.gd`의 영웅별 고정 3공격+방어. 획득/교체/레벨/변형 없음 | 장착·교체·성장·변형 가능한 실제 스킬 데이터 | 장착 슬롯·비용·레벨 표·해금·변형 관계 |
| EffectResolver | `act()`와 `_resolve_attacks()` 내부에 직접 처리 순서가 있음 | 상태 이상·연쇄·회복·자원 변경의 명시적 순서 | 원작 사건 순서와 동시 발동/중첩 처리 |
| RelicSystem | 5개 중복 없는 패시브가 모두 자동 적용. 추가 획득은 재4로 대체 | 유물 장착·트리거·스킬 작동 변경 | 실제 유물별 조건, 슬롯/중복/발동 순서 |
| EnemyBehavior | 단일 적과 고정 3부위. 일반 3종은 기본 공격원 순환 공유. Judge/Pale 추가 의식은 자체 규칙 | 일반/정예/복수 적·자세·보스별 행동 데이터 | 원작 조우 구성과 파괴 후 행동 변화. 자체 보스 규칙은 정답이 아님 |
| RewardSystem | 승리 후 회복24HP/3집중, 금화25/재2, 무작위 미보유 유물 중 하나 | 실제 보상 단계·스킬/유물 선택·Empower 적용 | 제공 순서·선택 수·중복·등급·강화 확률/조건 |
| PartySystem | Mara/Ivo/Sable 고정 시작. 선택 영웅·동료 영입·이탈 없음 | 5명 목표 영웅의 선택·역할 대응·동료와 Sigil | 목표 버전의 로스터, 시작 구성, 영웅/NPC 행동 참여 |
| WorldMapSystem | 9구간, 3/6/9는 고정 보스, 나머지는 두 선택지. 상점/마을 시스템 없음 | 실제 3월드·노드·시설·해금·자원 이월 | 생성 규칙·월드 진입/종료·전투 간격·노드 종류 |
| KarmaSystem | 사건 선택과 절단으로 단일 수치 변화. 음수면 다음 적 부위 방어막 +1 | 실제 Virtue/Sin 조건과 NPC/보상/전투 반응 | 단계·트리거·반복·재등장·제한 표 |
| MetaProgression | 승패 시 재를 한 번 정산. HP+5/공격+2/집중+1을 최대5단계 구매 | Soul·Fate Prayers·Sigil·시설·영웅/스킬/유물 해금 | 획득·가격·상한·해금 연결. Ash를 Soul로 임의 환산하지 않음 |
| SaveMigration | v1/v2 저장, 쌍 파일 체크포인트·백업·충돌 거부·정산 1회는 검증됨 | 새로운 규칙 상태와 기존 여정/금고를 안전하게 구분·이행 | 자원/캐릭터/해금 대응표. 미확정 상태의 자동 변환 금지 |

## 코드 근거

- `model.gd`: `act`, `end_round`, `preview_action`, `preview_intent`, `_prepare_intent`, `_make_campaign`, `_open_event`, `_win_battle`, `choose_reward`, `buy_upgrade`, 저장/복구 함수
- `legacy/legacy_content.gd`: 기존 영웅·스킬·유물 정의
- `MODEL_API.md`: 현재 프로토타입의 공개 상태 및 처리 계약
- `rulesets/severed_v0_2_102/evidence.json`: 버전이 확인된 자료와 미확정 대상의 구분

## 재사용과 교체 경계

고유 배경·캐릭터 그림, 한국어 글꼴/번역 경계, 일반 입력 컨트롤, 저장 파일의 검증·백업 접근은 재사용 후보입니다. 그렇다고 고정 3인 배열, 3부위 가정, 자동 절단, 자체 의식 주기, 9구간 지도, 수치 강화가 원작과 같다는 뜻은 아닙니다. UI와 FX는 새 규칙이 정해진 뒤 영웅/NPC/적/부위를 식별자로 참조하도록 조정해야 합니다.

기존 여정은 원래 규칙으로 보존해야 합니다. 신규 규칙과 자원 대응이 확인되기 전에는 플레이어가 모은 자원과 진행을 임의로 바꾸거나 지우지 않습니다. 기존 저장 복구 검사가 통과했다는 사실도 아직 존재하지 않는 새 모델로의 이전 성공을 증명하지 않습니다.

## 검증의 의미

현재 회귀 통과는 모듈 분리 후 기존 동작과 저장을 유지했다는 근거입니다. 원작과의 동일 입력 비교, 새 빌드 성장 경험, 플레이 재미는 아직 검증하지 않았습니다. 원작을 실행하거나 버전·입력·앞뒤 상태가 확인되는 연속 기록을 확보한 뒤 각 행의 조건을 동결해야 합니다.
